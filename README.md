## `$ cat /var/log/security_research.log`

I focus on understanding how systems fail — not just how they work.

- **Attack Surface Analysis** — mapping what is exposed, what is trusted, and what shouldn't be
- **Web Application Security** — authentication flaws, injection points, logic vulnerabilities, broken access controls
- **Network Security** — traffic analysis, protocol behavior, misconfiguration discovery
- **Vulnerability Research** — analyzing CVEs, reproducing known issues, understanding root cause
- **OSINT** — passive reconnaissance, digital footprinting, open-source intelligence gathering
- **Security Automation** — building tools that make repetitive security workflows faster and more consistent
- **CTFs** — offensive challenges, web exploitation, forensics, reverse engineering, crypto

I approach security from an offensive research mindset: understand how an attacker thinks, then build defenses and tools informed by that perspective.

## `$ python3 ai_security_lab.py`

Combining AI with cybersecurity is one of the areas I find most interesting right now.

Not in the hype sense — in the practical sense: using LLMs as force multipliers for research tasks, building intelligent automation that adapts to security context, and experimenting with what becomes possible when you connect language models to real security workflows.

**Areas of active experimentation:**

| Area | Focus |
|---|---|
| LLM-powered recon | Automating OSINT aggregation and summarization |
| AI-assisted analysis | Using models to triage and annotate vulnerability data |
| Intelligent agents | Building agents that chain security tools autonomously |
| Local AI (Ollama) | Running models locally for privacy-sensitive security research |
| Security workflow automation | Reducing manual effort in repetitive assessment tasks |
| Prompt engineering for security | Designing prompts for CTF assistance, code auditing, threat modeling |

The goal is practical tooling, not demos.
